## Summary

- The hash is parsed and formatted entirely by `web/src/utils/squatRoute.js`, which handles only `guide`, `t`, `tab`, `m` and `paused`. The hook `useSquatHashState.js` reads it on load, follows `hashchange`, and writes with `history.replaceState`.
- There are no camera keys anywhere. `parseSquatHash` ignores unknown keys, and `formatSquatHash` rebuilds the hash from known keys only. A hand-written camera key therefore disappears on the next write.
- `tab` is parsed and formatted but nothing in the UI consumes it (no chart tabs exist). `paused` is also never read back: nothing consumes `hash.paused`, and playback never autostarts.
- `t` is applied once at load and later hash edits are not followed. `m` and `guide` do follow `hashchange`.
- The camera lives wholly inside the lazy 3D chunk. It is three.js `OrbitControls` with pan off, so the pose is three numbers: radius, polar, azimuth. The scene's public API has only setters and `camera.{reset,preset,orbit,zoom}`. There is no pose getter and no change callback reaching React.
- Two sets of polar limits exist: `cameraMath.js` defaults 0.01/3.13, and `sceneStyle.js` 0.15/1.62, which the scene actually uses. Distance limits agree at 0.6 and 6.
- `squatRoute.js` is imported statically by `RouteRoot.jsx`, so it sits in the main entry chunk, which both `/squat` and the dashboard load. Bytes added there count against both budgets (squat 116.6/117, dashboard 147.2/150 per the PR report).
- `cameraMath.js` is imported only by `createAnatomyScene.js`, so it is behind the lazy 3D boundary.
- No clipboard, `execCommand`, `navigator.share` or `select()` use exists anywhere in `web/src` (the one `.select()` hit is a Supabase query).
- Nothing in `vercel.json` mentions clipboard. The Permissions-Policy header lists only geolocation, microphone and camera.
- Neither the `content.test.js` scan nor the visual suite covers new component JSX strings or `/squat`. The gates a new control hits are `contrast.test.js`, e2e axe, the 44 px target check, and the 390 px layout-stability check.
- Not verified: iOS Safari and Android Chrome per-version support, and jsdom's native `navigator.clipboard` (see H).

Parse behaviour (lines 36-58):
- Default is `{guide:null, t:null, tab:null, m:null, paused:false}` (line 37). An empty or missing hash returns it (lines 38-39).
- The body is split on `&`. Each part is split on the first `=`. The value is `decodeURIComponent`'d; a throw skips that part silently (lines 44-50).
- Validation per key (lines 51-55):

| Key | Rule |
|---|---|
| `guide` | `GUIDE_PANE_IDS.includes(value)` |
| `tab` | `GRAPH_TAB_IDS.includes(value)` |
| `t` | `/^\d+(\.\d+)?$/` then `Number(value)`; no length or upper bound |
| `m` | `MUSCLE_SLUG_RE` |
| `paused` | any occurrence (bare, or `paused=x`) sets true; the value is ignored |

- Unknown keys fall through every branch and are dropped. A failed validation leaves the previous value in place, so for a repeated key the last valid value wins. `squatRoute.test.js:88-92` pins this for `m`.
- No total length limit exists anywhere. The only length limit is 64 characters on the `m` slug.

Format behaviour (lines 60-70):
- Emit order is `guide, t, tab, m, paused`, joined with `&` and prefixed with `#` (line 69). It returns `''` when nothing is emitted.
- `t` is emitted only if it is a finite number ≥ 0, as `toFixed(2)` (lines 63-65).
- `guide` and `tab` are emitted only if in their closed sets (lines 62 and 66). `m` is emitted only if it matches the slug regex (line 67). `paused` is emitted as the bare word when truthy (line 68).

Importers of `squatRoute.js` (grep over `web/src`):
- `web/src/RouteRoot.jsx:3` imports `canonicalSquatUrl` and `isSquatPath`. This is the main-entry importer.
- `web/src/squat/hooks/useSquatHashState.js:2` imports `formatSquatHash` and `parseSquatHash`.

- `GUIDE_PANE_IDS`, `GRAPH_TAB_IDS` and `MUSCLE_SLUG_RE` have no non-test importer outside `squatRoute.js` itself.

- Never written on:

### B2. Scene, hook and controls

Where state lives:
- The camera is a three.js `PerspectiveCamera` and `OrbitControls` created inside `createAnatomyScene` (`createAnatomyScene.js:390`). Pose exists only as `camera.position` relative to `controls.target`. There is no React state for it.
- Input is handled by three's `OrbitControls` (imported at `:22`): `enableDamping = !reducedMotion` (393), `autoRotate = false` (394), `enablePan = false` (395), `minDistance`/`maxDistance` (396-397), `minPolarAngle`/`maxPolarAngle` (398-399). `sceneParity.test.js:48-58` pins that keys and pan stay off.

Scene return object (`createAnatomyScene.js:575-636`): `canvas`, `poser`, `setDepth(s)`, `setLayers({muscles, skeleton, body})`, `setPalette(p, style)`, `setActivation(weights)`, `setReducedMotion(reduced)`, `camera: {reset, preset(name), orbit(dAz, dPol), zoom(f)}`, `dispose()`.

- `OrbitControls` `change` and `start` listeners exist only inside the scene (`:512-522`). `change` calls `invalidate()`; `start` cancels a running tween.
- `currentView()` (`:414-415`) reads the pose from `camera.position`, but it is private.
- `createAnatomyScene` options (`:88-100`) are `container, manifest, buffer, palette, style, reducedMotion, coarsePointer, onFirstFrame, onContextLost, onContextRestored`. No camera option is accepted.

Hook:
- `useAnatomyScene.js:66-84` calls `mod.createAnatomyScene`, then `ctl.setDepth(v.s)` and `ctl.setLayers(v.layers)` (85-86), then `setController(ctl)`. Initial view, theme and reducedMotion are read from the `latest` ref (37-40, 64).

Initial pose and reset:
- `homeView()` (`createAnatomyScene.js:402-413`) is `max(defaultDistance, framingDistance(M.radius, fov, aspect))` clamped, with `defaultPolar` and `defaultAzimuth`.
- `aspect` starts as 1 (`let aspect = 1`, line 402). The initial `place(homeView())` (line 426) runs before `resize()` is first called (line 544). So the initial placement uses aspect 1, and only a later Reset uses the measured aspect. This is read from the code, not run.

Buttons:

- Presets: radius kept; polar = π/2 − 0.08; azimuth from `PRESET_AZIMUTH` (`:614-621`).
- Orbit and zoom: `orbitBy` and `zoomBy` with scene limits (`:622-625`).
- `goTo` tweens unless reduced motion (`:426-436`). `tween` is cancelled on a user drag (`:518-522`). Resize changes only `camera.aspect` and the renderer size (`:524-532`), not the pose.
- `place()` (`:416-424`) sets `camera.position` directly with no clamp. Polar clamping happens in `OrbitControls`. Whether its `update()` re-clamps a directly set position is assumed from three's behaviour, not looked up.

`SquatStage.jsx:49-55` mounts the host div that receives the scene's canvas (`hostRef`).

## D. Platform and library boundaries

Sources: Context7 (`/mdn/content`, `/microsoft/playwright`, `/testing-library/user-event`). Every claim below carries its source.

### D1. `navigator.clipboard.writeText`

- Secure context required (MDN, `files/en-us/web/api/clipboard/index.md`: "Requires a secure context"). The promise rejects if clipboard access is denied (same source).
- `Clipboard.write()` throws `NotAllowedError` if writing is not allowed (MDN `clipboard/write/index.md`). `writeText` is documented with the same denial behaviour but its own exceptions list was not retrieved.
- Chromium: writing requires the `clipboard-write` permission or transient activation. A granted permission persists and further activation is not required. The Permissions-Policy `clipboard-read`/`clipboard-write` must be allowed for `<iframe>` elements that access the clipboard (MDN Clipboard API, "Security considerations").
- Firefox and Safari: writing requires transient activation. The `clipboard-read` and `clipboard-write` permissions are not supported (MDN, same section).
- Fallback: nothing in the retrieved MDN content describes a fallback API. In-repo, none exists (C3).
- Not verified: per-version support on iOS Safari and Android Chrome. Browser-compat data did not come back from Context7, and MDN was not fetched with `curl`.

### D3. Testing the clipboard

- `@testing-library/user-event` is `^14.6.8` (`package.json:61`). Per Context7 (`/testing-library/user-event`), `userEvent.setup()` runs `attachClipboardStubToView`, replacing `navigator.clipboard` with an in-memory stub exposing `read, readText, write, writeText`. `resetClipboardStubOnView` and `detachClipboardStubFromView` exist.
  - The squat tests use `userEvent.setup()` (e.g. `SquatScene.test.jsx:369-371`).
  - Whether jsdom itself provides `navigator.clipboard` without `setup()` was not looked up. `web/src/test-setup.js` contains no clipboard code (grep).
  - Vitest environment is `jsdom` (`vite.config.js:181`).
- Playwright is `^1.65.0` (`package.json:57`). Context7 resolved v1.64.1 as the latest listed, so docs for 1.65 specifically were not checked.
  - Per Playwright's `tests/library/permissions.spec.ts` (Context7): `context.grantPermissions(['clipboard-read'])`, plus `['clipboard-write']` on Chromium only. Then `page.evaluate(() => navigator.clipboard.readText())` reads it back.
  - There is no `clipboard-write` permission in WebKit and no clipboard permission in Firefox (same file's comments).

## G. Risks and gotchas

1. **Verified (`useAnatomyViewState.js:79-98`, R8)**: `t` seeds once, so a hash-only navigation to a different `t` in the same tab updates `hash.t` but not the view. `m` and `guide` do follow `hashchange` (`useSquatHashState.js:13-15`).
2. **Verified**: the `hashchange` handler replaces the whole state with the parse of the hash (`useSquatHashState.js:13`). Keys that the new hash lacks revert to defaults. A key the parser does not know never reaches state.
3. **Verified (`squatRoute.js:51-55`)**: `parseSquatHash` has no camera branch, and `formatSquatHash` has no emit path. Both need extending for any camera key to survive a read and a write cycle.
4. **Verified**: `tab` and `paused` have no consumer. Round-trip tests exist for them only at the parse and format layer.
5. **Verified (`createAnatomyScene.js:426, 544`)**: the initial camera placement uses `aspect = 1`. The first real aspect arrives at `resize()` after placement, so a narrow-aspect (phone) first view is not framed with the measured aspect. Reset uses the measured one.
6. **Verified**: there are two polar limit sets (`cameraMath.js:39` defaults 0.01/3.13 vs `sceneStyle.js:85-86` 0.15/1.62). "Clamped to cameraMath limits" is ambiguous between them. The distance limits are identical (0.6/6), and the scene's value is defined twice (`cameraMath.js:7-8`, `sceneStyle.js:83-84`).
7. **Verified**: `CameraControls.jsx:188` hard-codes the 15° step and zoom factors independently of `cameraMath.js`.
8. **Verified**: `t=<400 digits>` passes the `/^\d+(\.\d+)?$/` check, `Number()` gives `Infinity`, and `frameAt` (`rep.js:31-34`) returns frame 0 for a non-finite value. `t=99` clamps to the last frame instead. Read from the code, not executed.
9. **Verified (`useSquatHashState.js:19-29`)**: the `replaceState` side effect runs inside a `setState` updater (see A2).
10. **Verified**: an open guide dialog sets siblings `inert` (`GuideDialog.jsx:47-60`), so any control outside the dialog is unreachable while it is open. `smallTargets` also skips `[inert]`.
11. **Verified**: `paused` is written together with `t` and is never reset to false. After a Play, the hash can still read `…&paused` while the page is playing, until the end-of-play write.
12. **Verified**: `canonicalSquatUrl` preserves `search` and `hash` (`squatRoute.js:13-15`), and `RouteRoot` runs it at module evaluation (`:30-37`).
13. **Verified**: there is no existing selectable-field, toast or status-line component other than the patterns in C2.
14. **Assumed**: `OrbitControls.update()` clamps polar for a pose set directly by `place()`. I did not look this up.
