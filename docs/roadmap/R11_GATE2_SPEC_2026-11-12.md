## Orchestrator amendments

Where these differ from the spec, these are what goes to the builder unless Scott says
otherwise.

1. **Status lifetime (a gap).** The spec does not say how long "Link copied." stays. Left
   up, it sits beside a view the user has since changed. It clears after about 4 seconds.
   The two fallback messages stay while the field is open. Question 3 below.
2. **`update()` returns the previous state object when the patch changes nothing.**
   Clear-on-change calls it on every camera gesture. Skipping `replaceState`, as the spec
   has it, is not enough: a new state object re-renders the whole tool each time. React
   skips the render when the next state is the same object (react.dev `useState.md`, via
   Context7). #464 tracks that re-render cost.
3. **No ref is needed for `getLink`.** The click handler can call the current render's
   closure. If the builder keeps a ref, it is written in an effect, as `useAnatomyScene`'s
   `latest` ref is.
4. **Byte arithmetic.** The squat rows in the spec's file table add up to about +3.0 KB
   gross, roughly +2.5 KB net of the 0.5 KB that leaves the shared chunk, not the +2.2 KB
   in §9. The +3.0 KB ceiling stands, with less margin than the spec implies. If Build
   measures over it, it stops and reports, as §9 says.
5. **e2e history assertion.** Setting `location.hash` in a test adds one history entry by
   itself. The assertion is that the tool adds none on top of it.

# Workflow Architect spec (verbatim)

# R11 share-a-view v1 (#439): Stage 3 spec

I read the code at the R8 head `1c6985a` (scratchpad `r8-head`). Line numbers are hints only. The stage was read-only and I wrote no files.

## 1. Summary

1. A **Share** card goes in the controls column, after `ViewOptions`. It holds a "Copy link" button, a status line that is also a polite live region, and a read-only link field that appears only as the fallback. It renders on every path, including no-3D, and is disabled until the rep data has loaded.
2. Pressing it builds the link in the click handler from live values: `view` (time, layers, heatmap), the hash (`m`, `tab`), and the scene's pose read on demand. It then calls `navigator.clipboard.writeText` before any `await`.
3. The hash gets three new keys, each omitted when it holds the default: `cam=<az°>,<pol°>,<dist m>`, `hide=<layers>` and bare `heat`. They are emitted after the existing `guide,t,tab,m,paused`, so every link that exists today is byte-identical.
4. Parse and format move out of the shared `utils/squatRoute.js` into a new `squat/utils/squatHash.js`. This takes bytes **off** the dashboard entry. The pure pose maths goes in a new `anatomy/utils/cameraPose.js`, which has the 95/95/90 gate.
5. `useSquatHashState` gains an **arrival counter**. It goes up only on `hashchange`, and replaceState never fires `hashchange`. The view and the scene re-apply the whole link on each arrival, and never on the tool's own writes.
6. The scene gains `initialPose`, `onUserCamera`, `camera.pose()` and `camera.setPose()`, plus a `home` flag, so a default camera is detected without any float comparison.
7. Camera and layer keys stay in the address bar only until the user changes that part of the view. A user change clears the key. A no-3D device cannot change them, so they survive a re-share from it.
8. Golden links are pinned at the parse/format level and at the opened-view level. The e2e suite grows to cover camera, layers, heatmap, a refused clipboard, a hashchange and the no-WebGL path.

## 2. Design decisions

| Decision | Chosen | Rejected | Why |
|---|---|---|---|
| Telling own writes from real navigation (trap a) | `useSquatHashState` returns `arrival`: 0 at mount, +1 on each `hashchange`. Consumers re-apply when it changes. | Diff the hash state against the view; a "suppress next change" flag around `update()` | `replaceState` does not fire `hashchange` (MDN `hashchange_event`, via Context7 in the research map, D4), so the event is already the clean signal. A counter cannot race and has no window in which it can be stuck true. |
| Stale keys (criterion 10) against pass-through (criterion 9) (trap b) | **Clear on change.** A user camera action clears `cam`, a layer toggle clears `hide`, a heatmap toggle clears `heat`. Nothing else ever writes those keys. On no-3D the controls do not exist, so the keys stay and Copy re-emits them. | Strip on load (a reload loses the camera, and the link is rewritten on open, against R8's e2e "opening a link does not rewrite it"); track continuously (Decision 3 rejected it) | Keys that are still on screen may stay, and keys the screen has left are removed at the moment of the change. That satisfies criterion 10 exactly and needs no device-specific branch. |
| Where parse/format lives (trap c) | Move `parseSquatHash`, `formatSquatHash`, `GUIDE_PANE_IDS`, `GRAPH_TAB_IDS` and `MUSCLE_SLUG_RE` into `squat/utils/squatHash.js`. `squatRoute.js` keeps only `isSquatPath` and `canonicalSquatUrl`. | Extend `squatRoute.js` in place | Bytes in `squatRoute.js` count against both entries. Its only non-test importer of parse/format is `useSquatHashState`, which is in the squat static graph. Moving it costs squat about nothing net and frees an estimated 0.4–0.6 KB on the dashboard entry. |
| Camera key shape | One atomic key, `cam=az,pol,dist`. The angles are whole degrees, the distance is in metres to 2 dp. | Three keys `az/pol/dist`; radians | Atomic means a half-valid pose is ignored whole, never half-applied. Degrees are short and readable. 1° at 3.6 m moves the camera about 6 cm, which is invisible. |
| Default camera detection (trap g) | The scene keeps a `home` boolean: true at build without `initialPose` and after Reset, false after any user camera action or `setPose(pose)`. Copy omits `cam` when `home`. | Compare floats against `homeView()` | The home radius depends on aspect (`framingDistance`), and the first placement uses `aspect = 1`. A float compare would be wrong on phones. |
| Applying a link pose in an open tab | Instant `place()`, with any tween cancelled | Tween 320 ms | Time, layers and muscle change at once on arrival, so the camera should too. A link without `cam` returns the camera to home: "keys absent revert to defaults", as `parseSquatHash` already does. |
| Starting pose (trap d-ii) | `createAnatomyScene({ initialPose })` places it **instead of** `homeView()`, before the first `render()` | Build at home, then `setPose` | There is no first frame at home, so there is no jump. `resize()` only touches aspect and projection, so the pose survives the aspect update. |
| Copy during a preset tween (trap j) | `pose()` returns the tween's **destination** | The instantaneous mid-tween pose | The user asked for the destination; a blend is a view nobody chose. It is also deterministic in tests. A residual from OrbitControls damping is read as-is: sub-degree, settling. |
| Copy during playback (approved edge case) | It carries `view.t` at the press. The handler never touches `view`, so playback continues. | Pause on Copy | Sound: playback never autostarts (`INITIAL.playing=false`), and a link applied on arrival always lands paused (see `link` action). |
| Frame 0 | The button omits `t` (and `paused`) at frame 0. The address-bar settle write is unchanged (it can still write `t=0.00&paused`). | Change R8's settle write | Criterion 5 says defaults are omitted. Both forms open the same view, and the golden test pins that. Not changing R8 keeps the diff smaller. |
| `guide` on the button | The builder sets `guide: null` explicitly | Pass `hash.guide` through | Decision 5. It is always null when the button can be pressed anyway, so being explicit makes the intent testable. |
| Re-apply rule | On arrival, the whole view becomes the link: time (missing means frame 0), layers, heatmap, camera; `playing:false`, `moved:false`. | Apply only the keys present | Matches how the existing `hashchange` already resets every missing key. `moved:false` keeps R8's settle write from rewriting the link just opened. |
| Sentry (criterion 4) | **Not reported** (expected non-events): `navigator.clipboard?.writeText` absent (this also covers an insecure context, where the API is not exposed: MDN "Requires a secure context"); a rejection whose `name === 'NotAllowedError'`. **Reported** through `captureError(err, {where:'ShareLink', stage})`: any other rejection, a synchronous throw from `writeText`, or a throw while building the link. Every branch shows a message and the field. | Report every refusal; report nothing | A denied permission is routine. An unknown error is a defect. Nothing is silent: the user always gets the link. |
| `t` of hundreds of digits | Fold in a one-line fix: parse caps `t` at `T_MAX = 600` s, then `frameAt` clamps to the last frame, as `t=99` does today | Leave it | The parser moves in this PR anyway, and criterion 7 requires a clamp rather than a silent jump to frame 0. Without the cap, the value re-emitted would be `Infinity` (dropped) or a 300-digit string. |

### Questions for Scott at Gate 2

1. **Where the control goes.** My recommendation is a "Share" card at the bottom of the controls column, after `ViewOptions` (after `TimeControls` when there is no 3D). You set up the view, then share it, and it sits where the camera and layer controls are. The alternative is a third button in the hero row next to "Coaching guide". 3. **The `t` cap fix (600 s) rides in R11.** Recommend yes (one line plus a test).
4. **Status wording.** Proposed text is in §7. Confirm that "Link copied." is enough, with no line describing what the link contains.

## 3. The URL contract (public from first send)

Shape: `<origin>/squat` + `#` + parts joined by `&`. No query string. The button always uses `window.location.origin + '/squat'`, so any `search` is dropped.

| Key | Grammar (parse accepts) | Emitted as | Units / precision | Default (omitted) | Validation / clamp | Emitted when |
|---|---|---|---|---|---|---|
| `guide` | one of `phases,metrics,measured,method,sources` | same | — | null | closed set | address bar only; the button never emits it (decision 5) |
| `t` | `^\d+(\.\d+)?$` | `toFixed(2)` | seconds, 2 dp | null (frame 0) | finite, ≥0, **capped at 600**; the view snaps to a frame (`frameAt`) and clamps to the last frame | button: frame ≠ 0, as `view.t`. Address bar: R8's settle write, unchanged |
| `tab` | one of `angles,moments,force,act,len` | same | — | null | closed set | passed through from `hash.tab`. R11 gives it no meaning |
| `m` | `^[a-z0-9-]{1,64}$` | same | — | null | shape at parse; a dead slug is dropped with the `STALE_LINK` notice (unchanged) | when `hash.m` is set |
| `paused` | bare, or with any value | bare `paused` | flag | false | — | exactly when `t` is emitted (button); R8's write is unchanged |
| `cam` | `^-?\d{1,4}(\.\d+)?,\d{1,3}(\.\d+)?,\d{1,2}(\.\d+)?$` (az, pol, dist) | `az,pol,dist` → e.g. `cam=53,76,3.60` | az and pol whole degrees; dist metres, 2 dp | absent (camera at home) | all three finite, or the whole key is ignored. az rounded, then wrapped to (−180, 180]. pol rounded, then clamped to **[9, 92]**: `ceil`/`floor` of the scene's 0.15/1.62 rad in degrees, so the quantised value never leaves the scene's range. dist clamped to [0.60, 6.00], then rounded to 2 dp. | button: scene ready and `!pose.home` → from the scene; scene not ready → `hash.cam` (cleaned) |
| `hide` | comma list over `muscles,skeleton`; unknown ids dropped; empty after filtering → key ignored | the ids in fixed order `muscles,skeleton`, deduplicated | — | absent (both on) | closed set | any layer is off in `view.layers` |
| `heat` | bare `heat`, or `heat=1` | bare `heat` | flag | absent (off) | any other value is ignored | `view.heatmap` is true |

- **Emit order (pinned):** `guide, t, tab, m, paused, cam, hide, heat`. The first five are unchanged.
- **Duplicates:** the last valid occurrence wins, as today for `m`; this applies per key, including `cam`. Unknown keys and malformed escapes are skipped (existing behaviour).
- **Fixed point:** `format(parse(format(parse(x)))) === format(parse(x))` for every input. "The cleaned value is what gets re-emitted" means exactly this. It needs no scene (trap e): on a no-3D device, `cam` is cleaned at parse against limits taken from `SCENE_STYLE.light.camera`. The limits are the same in both themes (`SCENE_STYLE.light = {...BASE, shadowOpacity}`).
- **Backward compatibility:** every shape that exists today parses and formats identically: `#t=2.44&paused`, `#t=1.00&m=soleus&paused`, `#guide=metrics&m=soleus&paused`, `#m=…`, `#guide=…`, `#…&tab=…`, and `/squat/` canonicalisation.

## 5. Interfaces (shapes only, no bodies)

**`anatomy/utils/cameraPose.js`** (radians unless the name says degrees; a pose is `{radius, polar, azimuth}`, as in `cameraMath.js`)
- `wrapAngle(rad: number) → number`, in (−π, π].
- `cleanPose(pose, limits: {minPolar, maxPolar, minDistance, maxDistance}) → pose | null`. Null if any field is not finite. Otherwise polar and radius are clamped and azimuth is wrapped.
- `degreeLimits(limits) → {minPol: int, maxPol: int, minDist, maxDist}`, with `minPol = ceil(deg(minPolar))` and `maxPol = floor(deg(maxPolar))`.
- `toDegrees(pose, limits) → {az: int, pol: int, dist: number}`: round, wrap az to (−180, 180], clamp pol to `degreeLimits`, clamp dist then round to 2 dp.
- `fromDegrees({az, pol, dist}, limits) → pose | null`: the inverse, then `cleanPose`.

**`squat/utils/squatHash.js`**
- `T_MAX = 600`; `CAM_LIMITS = SCENE_STYLE.light.camera` subset; `LAYER_IDS = ['muscles','skeleton']`.
- `parseSquatHash(hash: string) → HashState`, where `HashState = {guide: string|null, t: number|null, tab: string|null, m: string|null, paused: boolean, cam: {az,pol,dist}|null, hide: string[]|null, heat: boolean}`. Never throws.
- `formatSquatHash(state: Partial<HashState>) → string` (`''` or `#…`). It re-validates every field, so it is safe on unclean input.
- `camToPose(cam|null) → pose|null` (radians); `poseToCam(pose|null) → cam|null`.
- `shareState({ frame: number, t: number, m: string|null, tab: string|null, layers: {muscles: bool, skeleton: bool}, heatmap: bool, scenePose: (pose & {home: boolean})|null, carriedCam: cam|null }) → HashState`. Rules: `t`/`paused` only when `frame > 0`; `guide: null`; `cam = scenePose ? (scenePose.home ? null : poseToCam(scenePose)) : carriedCam`; `hide` = the ids that are off, or null; `heat = heatmap`.
- `shareUrl(origin: string, state: HashState) → string` = `${origin}/squat${formatSquatHash(state)}`.

**`useSquatHashState() → [state: HashState, update: (patch: Partial<HashState>) → void, arrival: number]`.** `arrival` is held in its own `useState`, incremented in the `hashchange` handler and never in an updater. `update` keeps the existing `replaceState`-inside-updater pattern. It is impure, but idempotent and development-only doubled: React's docs (Context7 `/websites/react_dev_reference`, useState troubleshooting) say Strict Mode calls updaters twice, development only, and `main.jsx` mounts `<React.StrictMode>`. The new skip-if-unchanged (`formatted === window.location.hash`, with `'' ≡ '#'`) keeps it idempotent. Nothing in R11 depends on the updater running once.

**`useAnatomyViewState(rep, link: {arrival: number, t: number|null, hide: string[]|null, heat: boolean})`.** Same return shape as today.
- The lazy reducer init takes layers and heatmap from `link`.
- New action `{type:'link', frame?: number, last?: number, layers, heatmap}` → `{...state, layers, heatmap, playing:false, moved:false, frame: frame === undefined ? state.frame : clampFrame(frame, last)}`.
- The effect on `[link.arrival]` dispatches the layers/heatmap part at once. The effect on `[link.arrival, info]` dispatches the seek (`t ?? 0` → `frameAt`) once per arrival, tracked in a ref. **This replaces R8's `seeded` ref.**

**`useAnatomyScene({...existing, pose: pose|null, arrival: number, onUserCamera?: () → void})` → `{status, errorKind, retry, camera}`**
- `pose`, `arrival` and `onUserCamera` go into the `latest` ref. The build passes `initialPose: latest.pose` and `onUserCamera: () => latest.onUserCamera?.()`, and records `appliedArrival = latest.arrival`.
- The effect on `[controller, arrival]` calls `controller.camera.setPose(latestPose)` when `arrival !== appliedArrival`, then updates the ref.
- `camera.pose() → (pose & {home: boolean}) | null` (null when there is no controller).

**`createAnatomyScene({...existing, initialPose?: pose|null, onUserCamera?: () → void})`**
- `initialPose` is cleaned with the existing `orbit(p,0,0,cam.minPolar,cam.maxPolar)` plus `clampDistance` (no new import), then `place()`d in place of `homeView()`. `home = !initialPose`.
- `camera.pose() → {radius, polar, azimuth, home}`: `tween ? tween.to : currentView()`.
- `camera.setPose(pose|null)`: cancel the tween; null means `place(homeView())` with the target reset and `home=true`; otherwise place the cleaned pose and set `home=false`. Then `invalidate()`. It does **not** call `onUserCamera`.
- `reset`, `preset`, `orbit` and `zoom` call `onUserCamera?.()`. Reset sets `home=true`; the others set `home=false`. The controls `'start'` listener (which already exists) also sets `home=false` and calls `onUserCamera?.()`.
- The debug probe gains `pose: () => camera.pose()`.
- Verified against the installed three `0.187.0`, `examples/jsm/controls/OrbitControls.js`:
  - `update()` rebuilds `_spherical` from `object.position` (`setFromVector3`), clamps `phi` to `min/maxPolarAngle` and the radius via `_clampDistance`, then calls `makeSafe()`. A directly placed out-of-range pose is therefore re-clamped on the next frame, so the scene-side clean is defence in depth.
  - `'start'` is dispatched on pointer-down rotate/dolly, on wheel (`onMouseWheel` dispatches start, then end) and on touch-start.
  - `getAzimuthalAngle`, `getPolarAngle` and `getDistance` exist, but read `_spherical` from the last `update()`. `currentView()` reads the live position, so it is used instead.
  - Source: the file itself, not Context7. three was not queried there because the installed source is the pinned version.

**`useShareLink({ getLink: () → string, enabled: boolean }) → { copy: () → void, outcome: 'idle'|'copied'|'blocked'|'unavailable'|'failed', message: string, link: string|null, fieldOpen: boolean, closeField: () → void, fieldRef, buttonRef }`.**
`copy()` is synchronous up to the `writeText` call: it bumps a sequence id, builds the link (catches, captures, shows `failed` + field), sets the message to `''`, and calls `navigator.clipboard.writeText(link)` in the same task. The promise's settle path updates state only if its sequence id is still the latest.

**`ShareLink` props:** `{ getLink: () → string, ready: boolean }`. It renders a `<section aria-labelledby="share-title">` card.

**SquatApp wiring**
- `const [hash, setHash, arrival] = useSquatHashState()`.
- `view = useAnatomyViewState(rep, {arrival, t: hash.t, hide: hash.hide, heat: hash.heat})`. Pass a memoised object or the fields; the hook keys on `arrival` only.
- `scene = useAnatomyScene({..., pose: camToPose(hash.cam), arrival, onUserCamera: clearCam})`, where `clearCam = () => setHash({cam: null})`. This is a no-op write when it is already null, thanks to skip-if-unchanged.
- `onLayer = (n, on) => { view.setLayer(n, on); setHash({hide: null}); }` and `onHeatmap = (on) => { view.setHeatmap(on); setHash({heat: false}); }`.
- `getLink = () => shareUrl(window.location.origin, shareState({frame: view.frame, t: view.t, m: selection.slug, tab: hash.tab, layers: view.layers, heatmap: view.heatmap, scenePose: scene.status === 'ready' ? scene.camera.pose() : null, carriedCam: hash.cam}))`. `getLink` reads through a ref updated each render, so the click handler sees the latest committed values.
- `<ShareLink getLink={getLink} ready={view.ready} />` is mounted after the `!sceneBlocked` fragment, outside it.

## 6. Flows and failure modes

**Press Copy.** Enabled ⇔ `view.ready` (the manifest has loaded, and the muscle index is built from the same manifest). Before that it is natively `disabled`, with a described reason. That answers "pressed before data has loaded": it cannot be.
1. The click handler builds the link synchronously.
2. If `navigator.clipboard?.writeText` is not a function, outcome is `unavailable`. The field opens. The message is "Copying is not available in this browser. The link is selected below." No Sentry event.
3. Otherwise `writeText(link)` is called in the handler. MDN (Context7 `/mdn/content`, Clipboard API "Security considerations") says Safari and Firefox need transient activation to write, and Chromium needs the permission or activation. Activation comes from the `pointerup` or `keydown` that produced the click (MDN glossary "Transient activation"). It expires after a timeout, so no `await` comes before the call.
   - It resolves: `copied`. "Link copied." No field. If the field is already open from an earlier press, it is closed.
   - It rejects with `NotAllowedError`: `blocked`. Field opens. "The browser blocked copying. The link is selected below." Not reported.
   - It rejects with any other error, or throws synchronously: `failed`. Field opens. Same visible text as blocked. `captureError(err, {where:'ShareLink', stage:'write'})`.
4. Building the link throws (it should not): `failed`, `captureError(..., {stage:'build'})`, and the field opens holding the current `location.href` with its search stripped. That is the best effort, and is better than nothing.
5. The field opens in an effect after commit: `focus()`, then `setSelectionRange(0, value.length)`. MDN (Context7) says `setSelectionRange` is valid on `type=text`/`url` and the highlight shows when focused; `select()` "does not necessarily focus". On iOS Safari, a programmatic selection after a gesture's microtask is **assumed** to work and **not verified**; the user can still long-press. Close (a button, or Escape in the field) hides the field and returns focus to Copy.
6. Pressed twice quickly: the second press sets the message to `''` and writes again. Only the latest sequence id settles state, so there is one field and the last message wins. The `''` → text transition makes a screen reader re-announce identical text.
7. Mid-tween: the link carries the tween's destination (§2). During damping it carries the live pose.
8. During playback: `view.t` at the press; playback continues untouched. Because `view.t` is the committed frame, it can lead the canvas by at most one frame (about 20 ms). Accepted.

**Open a link in a fresh tab.**
1. `RouteRoot` canonicalises `/squat/` (unchanged).
2. `SquatApp` mounts. `parseSquatHash` cleans every key; `arrival = 0`.
3. View init takes layers and heat; the switches render with the link's values from first paint, disabled.
4. The manifest arrives (`info`): seek to `t` (or frame 0), paused, `moved:false`, so nothing is written back.
5. Muscle: unchanged R8 path (held while loading, a stale slug gives the notice and a drop).
6. Scene: built with `initialPose = camToPose(hash.cam)`. Its first frame is at the link pose, so there is no default-then-jump. Layers and depth are set before `setController`, as today.
- Branches:
  - Chunk failure or WebGL missing: see the no-3D flow.
  - Context lost, then Retry: it rebuilds with the current `hash.cam`. If the user had moved the camera, `cam` was cleared and it rebuilds at home, which matches today's behaviour.

**`hashchange` in an open tab** (paste, manual edit). This deliberately changes R8: `t` now follows the hash.
1. The hook replaces state with the parse and `arrival++`.
2. The view dispatches `link` (layers and heat at once, seek once `info` exists). It stops playback and sets `moved:false`.
3. The scene effect calls `setPose(pose|null)`: instant, `home` follows. If the scene is not built yet, the build reads the latest pose.
4. Muscle and guide follow as today.
5. Nothing is written back to the address bar.

Known gap (assumed from the HTML spec, not verified): navigating to an **identical** fragment fires no `hashchange`. Pasting the same link again after only orbiting (where the link had no `cam`, so nothing was cleared) does not reset the camera. Accepted and documented.

**No-3D path** (`sceneBlocked`, or chunk or build failure).
- The manifest still loads (`useAnatomyData` docs: "the manifest still loads"), so time, muscle, guide and the form check restore.
- `cam` is cleaned at parse and kept in `hash.cam`. `hide` and `heat` are held in view state. No notice, no error.
- `CameraControls` and `ViewOptions` are absent (blocked) or disabled (failed), so nothing clears those keys.
- Copy: `scenePose = null`, so it uses `carriedCam`, and `view.layers`/`view.heatmap` re-emit the incoming values. Criterion 9 holds.

**Scene arrives after the link:** covered by `initialPose`. There is no flash because the first `render()` happens after `place(initialPose)`.

**R8 settle write after a link** (camera untouched): `{...prev, t, paused}` keeps `prev.cam`, which is still accurate. After an orbit, `cam` is already null. Criterion 10 holds.
