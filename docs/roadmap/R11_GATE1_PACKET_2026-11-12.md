## Orchestrator amendments to the story

The Product Manager's story is verbatim at the end of this file. Where these differ from
it, these are what goes to the Spec stage unless Scott says otherwise.

1. **A guide pane cannot be captured by the button as written (story AC6, AC8).** While
   the guide is open, `GuideDialog.jsx:47-55` makes everything outside the dialog inert,
   and closing it clears `guide` (`SquatApp.jsx:354`). A control outside the dialog can
   never be pressed with a pane open. Either the dialog carries its own control or the
   button's link covers the model view only. Decision 5.
2. **`paused` stays in the link whenever `t` is (replaces AC14's "neither emitted").**
   Issue #439 and R8 both define the link as `t` plus `paused`. Dropping it gives the
   button and the address bar two dialects, and removes the one marker that keeps
   already-sent links opening paused if a later item ever lets a link play. It costs seven
   characters.
3. **`tab` passes through when present (replaces AC15's "not emitted").** One formatter
   serves the address bar and the button, and R9 can then give `tab` meaning without
   touching sharing. R11 claims nothing about it.
4. **AC18: strike "including when the fallback field appears".** The 1 px gate measures
   load-time stability. A field that appears because the user pressed a control is not a
   layout shift in that sense. The control itself must still be laid out from first paint.
5. **AC19 reworded.** Where strings live is file placement, which is the Spec's call. The
   requirement is that new UI strings make no measured or recorded claim, and that the
   recipient always lands on the full tool with its "Modelled, not measured" label and its
   attribution footer. A chrome-less shared view is R27.
6. **AC5: an expected clipboard refusal is not a Sentry event.** A denied permission is an
   expected non-event, handled by showing the fallback. The Spec decides which failures
   are reported; none is swallowed silently.
7. **Added: the address bar never shows a stale view.** If Decision 3 goes with
   capture-on-press, a link opened with camera or layer keys must not leave those keys in
   the address bar once the user changes the camera or layers. Otherwise the next
   time-settle write publishes a mixed view.
8. **Added: the link format is a contract from the first send.** A small set of golden
   links is pinned in a test, so R9, R12–R14 or a data change cannot silently alter what an
   already-sent link opens.
9. **Added edge case: Copy pressed during playback.** The link carries the frame on screen
   at the press, and playback is not interrupted. Spec to confirm.
10. **The story's Decision 5 (query string) is folded into AC6 as a constraint.** A copied
    link is the origin, `/squat` and the known hash keys, nothing else. That follows from
    "no personal data in a link" and does not need a decision.

# Product Manager story (verbatim)

STAGE 2 STORY: R11 share-a-view v1 (#439). Written from the brief only. I read no code and ran nothing.

**1. Story**
As a coach, I want to copy a link that reopens /squat on the exact view I'm looking at (rep moment, muscle, guide pane, camera angle, layers) so that an athlete on a gym-floor phone sees what I meant without me describing it.
Persona and need are hypotheses. R1 (#433) has observed nobody yet. No learning-gain claim.

**Issue critique (it is incomplete in three places)**
- It omits the heatmap and layer toggles, the two things that most change what the recipient sees.
- "Clamped to cameraMath limits" is ambiguous. The scene's effective limits (distance 0.6-6, polar 0.15-1.62) differ from the module defaults (polar 0.01-3.13).
- It lists `paused` and `tab` as restorable. Nothing consumes either today, so "every hash key restores" is unassertable for them.

**2. Acceptance criteria**

*User-visible behaviour*
1. A "Copy link" control is present in the layout from first paint. It is disabled until it is usable, and has an accessible name.
2. On press, the link is built at that moment from the live view, including the current camera pose. It does not depend on the address bar having caught up.
3. With `navigator.clipboard.writeText` available and resolving, the clipboard holds the link. The copy runs synchronously within the tap's gesture.
4. If `writeText` is missing or rejects, a read-only selectable field holding the link appears. It is pre-selected and focused, and can be dismissed.
5. Success, failure and fallback each produce a visible message and the same text in a polite live region. A screen-reader user is told which of the three happened. Failure is also reported through `captureError()`, not swallowed.
6. A copied link contains only: `t`, `m`, `guide`, camera (azimuth, polar, distance), layer toggles and heatmap. It carries no query string and no other origin data. It always opens at `/squat`.
7. Default-valued keys are omitted (heatmap off, both layers on, default camera, no muscle, no guide). A pristine view copies as the bare `/squat` URL.
8. Opening a link restores every key it carries: time, muscle, guide, camera, layers, heatmap. A round-trip test enumerates every emitted key and asserts restore.
9. Camera values are clamped to the scene's effective limits (distance 0.6-6, polar 0.15-1.62). Azimuth is normalised. A non-numeric, NaN, Infinity or out-of-range value falls back to or clamps to a default and never throws. The cleaned value is what gets re-emitted.
10. Unknown keys, malformed values and duplicate keys are ignored silently. A dead muscle slug still shows today's "stale link" notice.
11. Same-tab hash change (pasting a new link into the open tab) updates the whole view: time, camera and layers, not only muscle and guide. This is a deliberate change to R8's "later hash edits are not followed" rule for `t`.
12. Hash writes keep replacing the history entry and add no Back steps.
13. Recipient with no 3D (no WebGL or chunk failure): time, muscle, guide, form check and list restore from the data alone. Camera and layer keys are ignored without error or notice. The Copy link control still works and preserves the camera and layer keys from the incoming link. A re-share must not strip what this device could not render.
14. Opening a link never autostarts playback. `paused` is neither emitted nor required. Old links containing `paused` still open fine.
15. The `tab` key is not emitted by the copy control. It is still parsed and tolerated (reserved for R9) and is not claimed as restored in R11.

*Standing constraints*
16. Budget: `SQUAT_ENTRY` stays at or under 117 KB (D9) as measured by `npm run build && npm run size` in the PR. Any growth to the shared URL module is also checked against the dashboard entry (147.3 of 150 KB). The PR body records both figures.
17. /squat does not import `supabaseClient.js` (`RouteRoot.test.jsx` stays green). No user data, identifier or free text enters a link. This includes the muscle-list filter text.
18. Axe is clean in light and dark. Touch target is at least 44 x 44 px at 360 and 390 px. The control pair's contrast is registered. There are no raw colour literals. Layout shift at 390 px is 1 px or less, including when the fallback field appears.
19. Any user-facing strings live in the content constants, so the honesty scan covers them. The control makes no claim that the view is "measured".
20. The e2e deep-link test is extended to cover time, muscle, camera, layers and heatmap, plus the clipboard-denied fallback. E2E runs in Chromium only.
21. Coverage thresholds do not drop. New code ships with tests.

**3. Edge cases**

| Case | Expected |
|---|---|
| Empty/null state (no hash, no muscle, no 3D) | Bare URL copies. Nothing throws. |
| `t` out of range (`t=99`) | Clamps to the last frame, as today. |
| Camera key out of range (`dist=999`, `pol=-5`) | Clamped per AC9. |
| Camera NaN, empty or repeated keys | Defaults. No error. |
| Link opened with a `?anatomy-debug` or tracking query | Copied link drops it (AC6). The open tab keeps it. |
| Link arrives before the 3D scene has loaded | Camera applied once the scene is ready. No flash of the default pose followed by a jump. |
| First-paint aspect square, then real aspect | A restored camera must not be re-framed by the aspect update. Reset still re-frames. Spec to confirm. |
| Insecure context or no clipboard API | Fallback field (AC4). |
| Permission denied or rejected promise | Fallback field and failure message. |
| Copy pressed twice rapidly | Idempotent. One field. The live region does not stack. |
| Offline | Copy works (local only). The link opens offline after a first visit. |
| Stale muscle slug | Notice, as today. The remaining keys still restore. |
| Auth/RLS | Does not apply. `/squat` has no auth, no Supabase import and no user data. |
| `M/D/YY` dates | Does not apply. No dates are in the view state. |
| Slow network | Partly applies. Only the 3D chunk load matters, covered by the rows above. |

**4. Out of scope**
- Charts and `tab` consumption: R9.
- Social preview image or unfurl text: R26 (H3, unapproved).
- Native share sheet (`navigator.share`) and QR codes. Nothing in the issue asks for them. Park them.
- Short links, accounts, messaging, or any sender-to-recipient tracking: VISION.md ("not a business").
- Theme, list-filter text and per-device preferences in links.
- Promoting links beyond the one current collaborator: gated on R2 (#434) and R1 (#433) per packet criterion 8. Building is allowed.
- Autostart of playback, or links that play.
- Refactoring bootstrap code to reclaim bytes, unless Scott chooses to fold it in (Decision 1).

**5. Decisions for Scott at Gate 1**

1. **Budget route.** Only 0.4 KB spare, and the URL module sits in the shared chunk.
   - (a) Land the bootstrap trim as its own item first. Your throwaway build reclaimed 11 KB on squat at +0.7 KB on the dashboard.
   - (b) Fold the trim into R11's PR.
   - (c) Squeeze R11 into 0.4 KB.
   - Recommend (a), ~75% confidence. It ships an 11 KB reclaim reviewed on its own, and it fits D6 (one roadmap PR open at a time) if sequenced after #463. R11 is blocked until #463 merges anyway, so the order costs nothing. (b) mixes a bundler-behaviour change into a feature diff. (c) is likely to fail, since 0.4 KB is smaller than a control plus camera parsing.
   - Changes downstream: whether the build starts on a clean 117 KB margin, and how many PRs there are.
2. **Include heatmap and layers in the link.**
   - Recommend yes, ~80%. A coach showing "this muscle is in the high band" sends a link that opens without it, which silently misleads. Cost is three small keys, omitted when default.
   - Alternative: camera only, matching the issue text.
3. **When the camera is captured.**
   - Recommend capture on button press only, ~70%. This needs the scene to expose its pose on demand, and keeps pose writes out of the address bar while orbiting.
   - The address-bar copier gets the time, muscle and guide but not the camera. I accept that and want it stated in the PR.
   - The alternative is continuous camera tracking in the address bar. That is more consistent, but costs write churn and bytes, and still has the same-tab gap.
4. **Same-tab navigation follows the whole view (AC11).**
   - Recommend yes, ~65%. A coach pasting a link into an open tab and seeing a half-applied view is a worse bug than the one it fixes. It reverses an R8 Gate 1 decision, so it is yours to confirm.
   - Alternative: leave R8 as is and document the gap.
5. **Query string dropped from copied links.**
   - Recommend yes, ~85%. A shared link should carry the view and nothing else, and this matches "no personal data in a link".
   - Alternative: preserve it. That is more faithful to the open tab and leaks whatever another app appended.

**6. Assumptions and unknowns**
- Verified only by the orchestrator (checks I did not repeat): `paused` and `tab` are unconsumed, the parser never throws, the camera limits, the entry budget figures, and the 11 KB trim measurement.
- Taken on trust: Stage 1's claims about the first-paint aspect behaviour (read from code, never observed), the Reset button's re-framing, and the clipboard gesture requirements.
- Not verified: iOS Safari and Android Chrome clipboard support (the Spec stage settles it). Whether a restored camera survives the aspect update. Whether the scene can expose its pose on demand (Spec).
- No coach or lifter has been observed using /squat. The persona value of this feature is untested until R1 completes. The H1 done-when, "a coach can send a link", can only be confirmed by a real send, not by the tests above.
- #463 must merge before the build starts. If it changes before then, these criteria need a re-check against the new head.
